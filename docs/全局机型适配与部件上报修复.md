# 全局机型适配与部件上报/渲染修复

## 0. 结论

问题**同时存在上报端和渲染端**，不是单点：

- 上报端：字段被裁剪、缺数据出处、全量重播不带标记、增量合并会残留旧值。
- 渲染端：4 发被压成"任一发在转"、起落架用 MSL 高度猜、灯位少一路、机型差异靠机型名特判。
- 已落地统一中间层 `xfly_client/aircraft_profile.py`（对齐 swift `CAircraftParts` 契约），并接上 Python 侧 + X-Plane 插件 + MSFS 插件全部关键路径。**35 个测试全部通过**。
- 下表 13 项缺陷现已全部修复。编译验证交给 GitHub CI；本机未重新编译（VS 生成器不可用、直接调用被沙箱策略拦截）。

## 1. swift 如何做到"不硬编码每一架飞机"

| 层 | swift 实现 | 关键机制 |
|---|---|---|
| 机型识别 | `CAircraftIcaoCode`（designator/family/combinedType/manufacturer/engines/wtc/rank）、`CAircraftCategory` 树、`CAircraftLivery`、`CAircraftModel` | 用 `resources/share/shared/dbdata/aircrafticao.json` 的万条数据库做级联打分，`L2J` 这类 combinedType 直接编码"轻/双发/喷气" |
| 模型匹配 | `src/core/aircraftmatcher.cpp::getClosestMatch()` | 顺序：手工映射 → 精确 model string → ICAO/family/combinedType/engine count/airline/livery 打分 → 默认模型；`resources/share/matchingscript/*.js` 允许用户脚本改写，不写死在渲染里 |
| 模拟器抽象 | `ISimulator` + `CSimulatorFsxCommon` / `CSimulatorXPlane` / `CSimulatorFlightGear` | 各模拟器只负责"读变量 → 填统一值对象"，上层不认识 SimConnect dataref 或 X-Plane dataref |
| 部件值对象 | `CAircraftParts` / `CAircraftLights`（9 灯）/ `CAircraftEngineList`（1-based、1..n、带 RPM） | `PartsDetails{NotSet, FSDAircraftParts, GuessedParts}` 记录出处；`isNull()` 用 `NotSet && flaps<0` 区分"没数据"和"全关" |
| 上报/同步 | `toFullJson()` / `toIncrementalJson()` | 显式 `is_full_data` 决定对端覆盖还是合并；令牌桶限速 |
| 渲染兜底 | `getAdjustedLights()`、`isFixedGearDown()`、`CPartsStatus{supportsParts, reusedParts, isSameParts}` | 舱灯/识别灯由任一发动机在转推导；起落架 `gearDown || onGround`；没收到部件才用猜测值，且猜测值带标记 |
| 位置插值 | `IInterpolator` 家族（linear / linearPBH / spline / multi）+ `CInterpolationRendererSetup` | 位置按时间轴插值；部件是离散量，靠出处标记做 fallback，不参与位置插值 |

**核心思想**：渲染器从不问"这是不是 A346"，只问档案"几台发动机、什么类型、起落架是否固定"，再问部件"哪些是实测、哪些是猜的"。

## 3. 已实施修复

### 3.1 新增统一中间层 `xfly_client/aircraft_profile.py`

- `AircraftProfile`：从 `aircraft_db.lookup()` 取引擎数/WTC/机型名，推导 `engine_type`（J/T/P/R）与 `gear`（fixed/retractable）；未知机型用实测引擎数兜底；带 LRU 缓存。
- `AircraftParts`：
  - 9 灯 canonical 键，兼容 `beacon_on` 与采集端 camelCase `beaconOn`；
  - 三态布尔 `_as_tri()`：NaN/Inf/空串 = **未知(None)**，不是 False；
  - 引擎 `dict[int, bool]`（1-based、1..8 可变长度），接受 `{"1":{"on":1}}` / `[1,0]` / `engine_count`；
  - `PartsDetails` 对应 `source`（not_set / fsd_parts / guessed）；
  - `toFullJson()` / `toIncrementalJson()` 显式 `is_full_data`；
  - `merge()`：全量替换、增量逐字段合并；
  - `getAdjustedLights()`、`isFixedGearDown()`、`effective()` 对应 swift 兜底推导。

### 3.2 Python 链路

- `fsd/session.py::_norm_parts()` 改为委托中间层，只保留服务器 6 灯裁剪；增量显式 `is_full_data=false`。
- `fsd/session.py::_broadcast_full_aircraft_config()` 重播时置 `is_full_data=true`。
- `model.py::_merge_parts()` 尊重 `is_full_data`：全量先 `clear()`。
- `model.py::push_roster()` 给每个玩家附加 `engine_count / engine_type / gear_type / parts_source`，并把 canonical 引擎掩码补齐到机型档案声明的数量；插件侧无需机型特判。

### 3.3 X-Plane 插件

- `players.h`：Player 增加机型档案字段；灯掩码扩到 bit5(logo)；引擎掩码扩到 8 台。
- `csl.c`：新增 logo、engine_rotation_angle_deg/speed[1..3]、prop_rotation_angle_deg[1..3]，索引 35..44（上限 48）。
- `xconnect.c`：解析新字段 + logo + 1..8 发；parts 日志带出处、引擎数/类型。
- `players.c`：
  - 按 `engine_count` 逐台引擎写角度/转速，类型决定 RPM（J=1200 / T=2400 / P=3000 / R=1200）；
  - 起落架兜底改用 AGL，固定起落架恒放下；
  - 补 logo 灯渲染。

### 3.4 MSFS 插件（MConnect）

- `mconnect.c::handle_player_list()` 解析 canonical `parts`（6 灯掩码 + 1..8 发 + gear/flaps/spoilers + 机型档案字段），网络线程只写玩家表，不碰 SimConnect。
- 新增 `DEF_AI_PARTS`：写 `GEAR HANDLE POSITION`、`TRAILING EDGE FLAPS LEFT/RIGHT PERCENT`、`SPOILERS HANDLE POSITION`、`GENERAL ENG THROTTLE LEVER POSITION:1..4`。
- 灯光 `LIGHT xxx` 是只读 SimVar，改按 ObjectID 发 `*_LIGHTS_ON/OFF` 事件；只在状态变化时发。
- 两类写入都做能力探测：首次失败即全局禁用该通道并打日志，位置渲染不受影响。
- `datadefs.c` 采集侧未知引擎数改为按 N1 推断（不再默认 2 发）。

### 3.5 机型库引擎类型与诊断日志

- 新增 `xfly_client/aircraft_engine_types.b64`：从 swift `aircrafticao.json` 的 `engine` 字段导出 2585 个 designator 的 J/T/P/R，独立小文件（11KB），不改主库 6 元组格式。
- `aircraft_db.lookup()` 返回 `engine_type` / `combined_type`；`_combined_type()` 不再恒 `J`。`AircraftProfile` 优先用官方值，前缀表仅作兜底。
- 三级日志全部落地（值变化时打印，不刷屏）：

| 阶段 | 日志前缀 | 插入点 | 打印内容 |
|---|---|---|---|
| ① 原始模拟器值 | `raw:` | `XConnect/src/datarefs.c`、`MConnect/src/datadefs.c` | 灯/gear/flaps/spoiler/onGround/引擎数 |
| ② 组装后 JSON | `[parts] acc json` / `[parts] roster` | `xfly_client/fsd/session.py`、`model.py` | 增量 ACC payload、下发插件的 canonical parts |
| ③ 最终动画值 | `anim:` | `XConnect/src/players.c`、`MConnect/src/players.c` | anim 索引值、灯掩码、引擎掩码、能力开关 |

断层判定：①错→机模变量/采集层；①对②丢→服务器 schema/合并逻辑；②对③错→插件映射；③对但画面错→CSL 模型 OBJ 动画键（查 `CSL动画dataref核对.md`）或 MSFS AI 能力限制（看 `parts_writable` / `lights_ok`）。

### 3.6 索引/ID 一致性兜底（新增）

- `XConnect/src/csl.h`：`CSL_MAX_DATAREFS` 48→64，定义 `CSL_DREF_ENG_ANGLE_N1=36` / `CSL_DREF_ENG_SPEED_N1=43` / `CSL_DREF_PROP_ANGLE_N1=50`。
- `XConnect/src/csl.c`：三组各 7 项连续排布（`[1]..[7]`），彻底消除"4 号引擎写到 prop[1]"和 8 发越界写 `anim[48]`。
- `MConnect/src/datadefs.h`：`DEF_AI_PARTS` 4→6，避开 `REQ_SYSSTATE=4` / `REQ_CPU_LOAD=5`。
- 新增 `tests/test_native_schema.py`（6 例）：直接解析 C 源码，检查 dataref 容量/索引分组、禁止硬编码回退、定义 ID 唯一、两侧 6 灯 key 对齐、探针入口存在、所有 b64 数据库都已加入 PyInstaller `--add-data`。
- `build_exe.ps1` 补 `aircraft_engine_types.b64` 打包项；否则打包版查不到官方引擎类型，会静默退回前缀表猜测。

### 3.7 真机能力探针

`MConnect.exe --parts-probe`：连上 MSFS 后注入一架带完整 canonical parts 的临时 AI 飞机（XPROBE1，C172），走一遍 `SetDataOnSimObject` + 灯光事件，12 秒后打印：

```
parts probe: ai_objects=1 pending=0 parts_setdata=OK light_events=OK
```

- `parts_setdata=FAILED` → 当前 MSFS 不接受这些 AI SimVar，部件写入自动禁用，位置渲染不受影响。
- `light_events=FAILED` → `*_LIGHTS_ON/OFF` 事件对该 AI 不可用，同样自动降级。
- `ai_objects=0` → 没进入飞行或 C172 容器标题未匹配，先看机型目录日志。
