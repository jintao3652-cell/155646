# 客户端在线更新（整包 exe 自更新）

客户端启动后自动检查一次更新，发现新版本时在 LCD 主屏右下角提示，点进去是
独立的「更新」小屏：下载（断点续传）→ MD5 校验 → 拉起更新助手 → 退出主程序
→ 助手替换 exe → 重启。

> 插件（`XConnect.xpl` / `MConnect.exe`）**不在**这条通道里：它们被模拟器占用、
> 更新时机不同，仍走 `XUpdate更新器.md` 的清单通道。本通道只更新客户端本体。

---

## 1. 接口约定

客户端只发一次 GET（无签名、无 body），响应是一个 JSON 对象：

```json
{
  "softwareName": "XFlySim Client",
  "version": "1.0.1",
  "logs": "1. 修复 FSD 断线重连偶发失败\n2. 优化 CSL 模型匹配速度",
  "link": "https://your.host/xflysim/releases/1.0.1/XFlySimClient.exe",
  "md5": "d1484281d8a142f35eee0f05707ecaee",
  "createdTime": "2026-11-27 15:30:00"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `softwareName` | 否 | 展示用产品名（更新小屏/日志）。 |
| `version` | **是** | 远端最新版本，如 `1.0.1`、`v1.0.1`。只比数字段大小（`1.10 > 1.9`），后缀（`-beta`）忽略。 |
| `logs` | 否 | 更新说明，原样显示在更新小屏；可以是字符串（支持 `\n`）或对象（自动转 JSON 文本）。 |
| `link` | 是* | 新客户端 exe 的直链（`http` / `https` / `file`）。*只有版本比本地新时才会用到。 |
| `md5` | 否** | 整包 MD5（32 位十六进制）。**强烈建议填**：没有它就只能凭响应长度判断完整性。 |
| `createdTime` | 否 | 发布时间，原样显示。 |

校验规则（`xfly_client/update_service.py::parse_update_info`）：

- 不是 JSON 对象、`version` 不是数字开头的版本号 → `update_bad_response`；
- `md5` 不是 32 位十六进制 → `update_bad_response`；
- `link` 协议不是 http/https/file → `update_bad_link`。

响应支持 UTF-8 BOM（`utf-8-sig`），上限 1 MB。

### 版本比较

只比版本号，**不做任何本地文件哈希**：

- `1.0.1 > 1.0.0`、`1.10 > 1.9`、`1.0 == v1.0.0`、`1.0 == 1`（补零对齐）；
- 远端不比本地新（相同或更旧）→ 判定"已是最新"，不下载、不降级。

## 2. 配置：更新接口地址填在哪

`srv` 地址只有一个空位，在 **`xfly_client/update_service.py` 顶部**：

```python
# ---------------------------------------------------------------------------
# 更新接口地址：把下面这个空字符串填成你的检查更新接口即可（例如
# "https://api.xflysim.com/client/version"）。留空 = 关闭启动自动检查，
# 界面上也不会出现任何更新提示。
# ---------------------------------------------------------------------------
UPDATE_API_URL = ""
```

- 留空 = 功能整体静默关闭（不请求、不提示，更新小屏显示"未配置更新地址"）；
- 调试/私有部署可用环境变量 **`XFLYSIM_UPDATE_URL`** 临时覆盖（优先级更高），
  便于本地起个假接口联调；
- 若要改版本号来源，只需改 `xfly_client/version.py::CLIENT_VERSION`（界面右下角
  版本号也从后端读，不再硬编码在文案里）。

## 3. 更新流程（先起助手，再退主程序）

```
① GET 检查接口                     只比版本号；启动时自动查，失败静默
② 下载到临时目录                   %TEMP%\XFlySimUpdate\<version>\<文件名>.part
   - 断点续传                      HTTP Range: bytes=N-，服务端 206 才续；
                                  返回 200（不支持 Range）则清空重下，不会拼坏包
   - 边下边算 MD5                  续传前先把已有 .part 喂进哈希
③ 校验                             长度>0 + MD5 一致；不一致删除 .part 并报错
④ 写作业文件 + 拉起 XUpdate.exe    <TEMP>\XFlySimUpdate\<version>\update-job-<pid>.json
⑤ 主程序退出                       前端收到 restarting 事件后 win_close
⑥ 助手等 PID 退出                  最多 60s，之后仍尝试替换
⑦ 校验安装包                       MZ/PE 头，防止拿 HTML 错误页覆盖 exe
⑧ 备份 → 原子替换                  旧 exe 改名 .exe.bak；包复制到同目录 .update-new
                                  再 os.replace（同卷原子 rename，跨盘也成立）
⑨ 写回版本号                       %APPDATA%\XFlySim-Client\update-installed.json
⑩ 重启新版本 + 助手退出             结果写 update-result.json，下次启动提示
```

为什么必须有独立助手：Windows 上正在运行的 exe 不能被自己覆盖。所以主程序只负责
「下载 + 校验 + 拉起助手」，替换由助手在客户端退出后完成——**先启动助手再退出**，
避免"客户端关了但助手没起来"。

### 失败与回滚

| 阶段 | 失败时 |
|---|---|
| 检查 | 启动自动检查：只写 DEBUG 日志，不打扰；手动"重查"：LCD/日志提示原因 |
| 下载 | 保留 `.part`，下次点更新继续续传；`error` 状态带错误码 |
| MD5 | 删除 `.part`（避免永远续传坏包），提示校验失败 |
| 替换 | `.bak` 还原旧 exe；旧文件未被改动，客户端可正常打开 |
| 占用 | 重试 12s（杀毒/索引释放句柄）；仍失败 → 还原 + 弹窗"文件被占用" |
| 重启 | 更新已完成，只记 WARN 日志，不算失败（用户手动打开即可） |

助手在客户端退出后没有窗口可提示，失败时用 `MessageBoxW` 弹窗，并把原因写进
`update-result.json`；下次启动客户端会读一次并提示（读完即删）。

## 4. 代码与文件位置

| 位置 | 作用 |
|---|---|
| `xfly_client/update_service.py` | 接口地址常量、响应解析、版本比较、`Downloader`（续传+MD5）、作业文件、`UpdateManager` 状态机 |
| `xfly_client/update_apply.py` | 更新助手核心：等进程退出、PE/MD5 校验、备份/替换/回滚、重启、结果落盘 |
| `xupdate.py --apply-package` | 助手入口（随 `XUpdate.exe` 打包） |
| `webapp.py` → `Api.get_version / check_update / apply_update / update_state` | 前端可调用的后端接口；启动时自动检查并汇报上次结果 |
| `webui/src/components/Screen/Update.vue` | 更新小屏（LCD），路由 `/update` |
| `webui/src/components/Screen/Main.vue` | 主屏右下角"更新 x.y.z"角标（与"新消息"共用一格） |
| `%TEMP%\XFlySimUpdate\<version>\` | 下载暂存（`.part`、作业文件；可被 `XFLYSIM_UPDATE_DIR` 覆盖） |
| `%APPDATA%\XFlySim-Client\update-result.json` | 助手结果（下次启动读一次即删） |
| `%APPDATA%\XFlySim-Client\update-installed.json` | 已安装版本记录（版本号写回） |
| `logs/xupdate-YYYY-MM-DD.log` | 助手日志（复用 XUpdate 的分日日志，与 `xflysim-*.log` 分开） |

状态机（推给前端的事件 `update`）：

```
disabled ← 未配置接口地址
idle → checking → available | uptodate
                        ↓
                 downloading（percent/received/total）
                        ↓
                   restarting（前端随即退出）
error（带 errorCode；启动自动检查失败时 silent=true）
updated（仅"上次更新成功后的首次启动"）
```

## 5. 界面

1. 启动 → 自动检查（静默）；
2. 有新版本 → LCD 主屏右下角闪烁 `更新 1.0.1`（下载中显示百分比），点击进入更新屏；
3. 更新小屏：`当前 1.0.0 → 最新 1.0.1`、更新说明、`更新 / 重查 / 稍后`；
4. 点"更新" → 应用内确认框（会断开当前连线）→ 进度条 → "正在重启…" → 自动退出；
5. 重启后日志提示"已更新到版本 x.y.z"。

文案三语（`en` / `zh-CN` / `zh-TW`），错误码映射到 `errors.updateXxx`，未知码回退
显示后端原文。用户点"稍后"只在本次运行内不再闪角标，下次启动会重新检查。

## 6. 打包与发布要求

- `build_exe.ps1` 会同时产出 `dist\XFlySimClient.exe` 与 `dist\XUpdate.exe`；
  **两个文件必须放在同一目录**——客户端在 `base_dir` 找 `XUpdate.exe`
  （源码运行时回退 `python xupdate.py`，便于开发调试）。
- 发布包必须是**单个 exe**（当前只支持整包替换；`link` 指向 exe）。
  目录版（`-OneDir`）不适用该流程。
- 服务端建议：
  - `link` 指向 CDN/静态文件，支持 `Content-Length`，**建议支持 `Range`**
    （客户端才能续传）与稳定的 `ETag`/`Last-Modified`；
  - `md5` 必须与新包一致（发布脚本里 `md5sum` 生成后写进接口）；
  - 版本号用 `1.0.1` 这类递增数字，不要用日期当版本（`2026-11-27` 也能比，但
    语义上容易与 `1.x` 打架）；
  - 接口做 `Cache-Control: no-cache`（客户端已带该请求头，服务端配合更好）。

## 7. 自测

```powershell
python -m unittest tests.test_update_service tests.test_update_apply -v
```

覆盖：版本比较（含 `1.10 > 1.9`、补零、后缀、非法值）、接口解析（缺字段/坏 md5/
坏协议/logs 为对象）、**断点续传**（有 Range 206 续传、无 Range 回 200 清空重下）、
MD5 不一致删包、下载取消、作业文件读写与路径校验、助手定位（XUpdate.exe /
xupdate.py / 缺失）、替换成功、**替换失败回滚**、PE 头校验、结果与版本落盘。

手工验证（需要能起本地 HTTP 服务）：把 `XFLYSIM_UPDATE_URL` 指向一个返回上述
JSON 的本地接口，`XFLYSIM_UPDATE_TARGET` 指向一个临时 exe（源码运行时用来
代替"自身"），点更新即可观察完整流程。

## 8. 已知限制

- **源码运行不能自更新**（`python webapp.py`）：目标 exe 是解释器，替换它毫无意义，
  因此 `apply_update` 直接返回 `update_unsupported`，提示使用打包版。
- 只替换客户端本体，不改 `XUpdate.exe` 自身；需要升级助手时随安装包一起分发新版
  `XUpdate.exe` 并重启客户端。
- 不处理 exe 之外的文件（配置在 `%APPDATA%`，本来就不随包走）。
- 不做差分/增量补丁，每次整包下载（配合续传，弱网重试代价可控）。
