# 资源层更新设计（CSL / FSLTL / AIG）

> 2026-11-27。目标：把体量巨大的他机模型资源从主程序强制更新通道里彻底拆出来，
> 做成可选、增量、可后台的资源层。日常启动**不做全量 MD5**。

## 1. 为什么必须拆开

本机实测（2026-11-27）：

| 资源 | 用途 | 位置 | 文件数 | 体积 |
|---|---|---|---:|---:|
| CSL（X-CSL） | X-Plane 他机模型，`XConnect` 用 | `X-Plane 12/Resources/plugins/XConnect/CSL/` | 11 206 | 见下方说明 |
| FSLTL | MSFS 轻量流量包/涂装，`MConnect` 扫 `SimObjects/.../aircraft.cfg` | `L:\MSFS\Community\fsltl-traffic-base` | 23 492 | 63 GB |
| AIG | MSFS 高细节 AI 机模/涂装，同上 | `L:\MSFS\Community\aig-aitraffic-oci` | 15 044 | 12 GB |

> CSL 的 `du -sh` 在本机跑到超时被中止（文件数太多）；仅 `B738` 一个机型目录就有 1 142 个文件。

结论：三类合计接近 5 万个文件、75 GB+。任何「每次启动逐文件算哈希」的设计都不可接受：
机械盘上要几分钟，SSD 上也会明显拖慢启动，而且绝大多数用户资源根本没变化。

## 2. 边界：主程序更新 vs 资源更新

| | 主程序 / XConnect / MConnect | CSL / FSLTL / AIG |
|---|---|---|
| 通道 | 版本 + 小包，强一致 | 独立资源通道，可选 |
| 触发 | 启动检查 / 用户点「检查更新」 | 用户主动安装或修复；后台补包 |
| 失败影响 | 无法运行 | 仅他机外观降级（白机/通用机） |
| 粒度 | 整包替换 | 机型包 / 航司包 / 基础包 |
| 校验 | 整包签名/哈希 | 平时不看，校验时按包 |
| 是否阻塞启动 | 可以短暂阻塞 | **绝不阻塞** |

资源缺失或版本落后时，MConnect / XConnect 必须照常工作，只是匹配降级到通用机。
资源层任何异常都不能阻止客户端连 FSD。

## 3. 日常启动：只做「存在性 + 清单版本」

实现：`xfly_client/resources.py::quick_check()`。

启动路径上最多做三件事：

1. `os.path.isdir(根路径)` —— 判断有没有装；
2. 读一个本地小 JSON 清单 `xflysim-resource-manifest.json`（几 KB，包级条目，不含逐文件哈希）；
3. 若提供了服务器清单版本（从缓存读，网络请求异步且带 TTL，超时不等待），比对版本号。

**禁止**在启动路径出现：`os.walk` 整棵树、逐文件 `stat`、任何哈希计算、打开 OBJ / aircraft.cfg。

状态机：

| state | 含义 | UI 表现 |
|---|---|---|
| `missing` | 根目录不存在 | 灰字「未安装」，不报错 |
| `unmanaged` | 目录在，但没有我们的清单（用户自己装的资源包） | 灰字「已安装（未纳管）」，**不覆盖** |
| `invalid_manifest` | 清单损坏/版本不认识 | 黄字「清单异常」，建议重新校验 |
| `ok` | 清单有效，版本匹配 | 绿字「就绪」+ 版本号 |
| `outdated` | 清单有效但服务器版本更新 | 黄字「有更新」，不自动下载 |

`unmanaged` 是重要边界：用户从 FSLTL / AIG 官方渠道自行安装的包，我们没有权力覆盖或删除。
只有带我们清单的目录才进入补包/更新流程。

## 4. 完整校验：只给用户主动触发

实现：`xfly_client/resources.py::verify()`。

- 入口：资源管理器页的「校验资源」按钮；或很久没校验时提示一次（建议阈值 30 天，且只提示一次）。
- 数据源：`xflysim-resource-verify-index.json`，逐文件 `sha256 + bytes + pkg`。**只在校验时读取**。
- 可按包过滤：`only_packages`。CSL 可按 ICAO 目录（如 `B738`）只校验当前常用机型；
  FSLTL / AIG 按航司包（如 `FSLTL_A20N_AAN`）过滤。
- 可限速：`max_bytes_per_sec`，按已读字节数 pacing；可暂停/取消：`should_cancel()` 回调。
- 输出按包汇总：`ok / missing_count / mismatch_count / checked_files / bytes`，不逐文件刷 UI。
- 校验只**报告**，不删除、不修复。修复走下面的增量补包流程。

## 5. 增量优于全量

包粒度约定：

- CSL：`CSL/<ICAO>/` 一个机型目录一包（`B738`、`A320`…），实测 `B738` 1142 个文件。
- FSLTL：`SimObjects/Airplanes/FSLTL_<ICAO>_<AIRLINE>[_VA]/` 一个航司涂装族一包。
- AIG：`SimObjects/Airplanes/` 下同名粒度；基础包（`manifest.json` / `layout.json` / `Traffic Files`）单列。

服务器清单（资源通道独立托管，不与客户端 release 绑在一起）：

```json
{
  "schema": "xflysim-resource-index",
  "version": 1,
  "generated_at": "2026-11-27T12:00:00Z",
  "resources": {
    "csl": {
      "resource_version": "2026-11-01",
      "packages": [
        {"id": "B738", "version": "3", "bytes": 12345678,
         "sha256": "...", "url": "https://.../csl/B738-v3.zip",
         "requires": []}
      ]
    },
    "fsltl": { "...": "..." },
    "aig": { "...": "..." }
  }
}
```

更新流程（包级）：

1. 对比本地清单与服务器清单的 `(id, version)`，算出待补包列表；
2. 下载到同盘临时目录 `<root>/.xflysim-tmp/<pkg>-<version>.zip`；
3. 校验整包 sha256 → 解压到临时子目录 → 按 verify-index 校验文件；
4. 原子替换该包目录（Windows 上若模拟器占用则延后并提示，不强杀进程）；
5. 更新本地 manifest，清理临时文件。

约束：

- 绝不做「整个 CSL 一个超大 zip 每次重下」；
- 不删除清单里没有的、用户自己放进去的包；
- 模拟器运行中只下载、不替换，等下次启动或用户确认后再切换；
- 下载限速、暂停、断点续传按包实现。

## 6. 本地文件布局

```
<资源根目录>/
├── xflysim-resource-manifest.json      # 小清单，启动只读这个
├── xflysim-resource-verify-index.json  # 逐文件哈希，只在校验时读
└── ...原有资源目录不动...
```

manifest v1：

```json
{
  "schema": "xflysim-resource-manifest",
  "version": 1,
  "kind": "csl",
  "resource_version": "2026-11-01",
  "generated_at": "2026-11-27T12:00:00Z",
  "packages": [
    {"id": "B738", "version": "3", "files": 1142, "bytes": 12345678}
  ],
  "index": "xflysim-resource-verify-index.json"
}
```

verify-index v1：

```json
{
  "schema": "xflysim-resource-verify-index",
  "version": 1,
  "kind": "csl",
  "resource_version": "2026-11-01",
  "files": {
    "B738/xsb_aircraft.txt": {"sha256": "...", "bytes": 123, "pkg": "B738"}
  }
}
```

## 7. 诊断导出集成

资源状态以摘要形式进入诊断 JSON 的 `extra.resources`：只含 `kind / state / resource_version /
package_count / has_verify_index`，**不含绝对路径**（诊断层已有用户目录替换与递归脱敏）。
用户反馈问题时可以直接看出「资源是否安装、是否纳管、版本是否落后」，而不用上传几万个文件名。

## 9. 风险与边界

- **符号链接**：Addons Linker 会用 junction / symlink，`os.path.isdir` 可跟随；校验时按路径读文件即可，
  但要防止索引里出现 `..` 逃出根目录（实现中已拒绝非相对路径）。
- **路径发现**：不硬编码 `L:` / `D:` 盘符；优先读环境变量 `XFLYSIM_CSL_ROOT` / `MSFS_COMMUNITY` /
  `XPLANE_ROOT`，找不到就如实报 `missing`，由用户在设置里指定。
- **MSFS 2020 / 2024 双 Community**：资源层只记录用户实际指定的那个根目录，不做多盘猜测扫描。
- **文件占用**：模拟器运行时 OBJ / aircraft.cfg 可能被锁，替换失败要保留旧包，不能留下半包。
