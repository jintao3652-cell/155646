# 变更说明：全局机型适配与部件上报/渲染修复

**日期**：2026-11-26  
**范围**：XFlySim-Client（Python 客户端）+ XConnect（X-Plane 插件）+ MConnect（MSFS 插件）  
**状态**：代码已落地，本地 Python 测试 35 项全通过；C 插件编译由 GitHub Actions 验证；MSFS 真机写入能力待跑一次探针确认。

---

## 1. 一句话总结

把"按机型名/固定 2 发/固定灯位硬编码"的部件上报与渲染，改成参考 swift pilotclient 的**统一机型档案 + canonical parts 中间层**；上报端保留数据出处，渲染端按档案属性驱动动画，并补齐跨模拟器（X-Plane / MSFS）的一致行为与诊断手段。

---

## 2. 解决的问题

| 现象 | 根因 |
|---|---|
| 他机发动机显示"启动但不转"、4 发只有一台转也全转 | 所有引擎动画写同一个 `any_engine` 值，且索引只覆盖 4 台 |
| 起落架不显示/误显示 | 用 MSL 高度 `<60ft` 猜地面，高原机场永远不成立 |
| 灯光状态不一致 | 灯掩码只到 5 位，丢失 logo；上报 6 灯、渲染只用 5 灯 |
| 对端重启后旧 gear/lights 残留 | 增量 ACC 无条件合并，全量重播不带 `is_full_data` |
| 螺旋桨机与喷气机动画语义相同 | 机型库 `_combined_type()` 恒返回 `J` |
| MSFS 端完全不渲染他机部件 | 声明了 parts 能力但只解析 `on_ground` |
| 无法定位断层在哪一层 | 没有"原始值 → JSON 值 → 动画值"对照日志 |

## 3. 主要改动

### 3.1 新增统一中间层（Python）

- **新增** `xfly_client/aircraft_profile.py`
  - `AircraftProfile`：designator → 引擎数/WTC/`engine_type`(J/T/P/R)/`gear_type`，带 LRU 缓存。
  - `AircraftParts`：对齐 swift `CAircraftParts` 契约——9 灯 canonical 键 + camelCase 别名、1–8 发可变掩码、三态布尔（NaN = 未知而非 False）、`source` 出处、`toFullJson()/toIncrementalJson()` 显式 `is_full_data`、`merge()`、swift 同款兜底推导（`getAdjustedLights()` / `isFixedGearDown()`）。
- `xfly_client/fsd/session.py`：`_norm_parts()` 委托中间层；全量重播补 `is_full_data=true`。
- `xfly_client/model.py`：`_merge_parts()` 全量先清空；`push_roster()` 给每个玩家附加 `engine_count / engine_type / gear_type / parts_source`，并补齐引擎掩码。

### 3.2 X-Plane 插件（XConnect）

- `players.h`：灯掩码扩到 bit5(logo)；引擎掩码 1–8；新增机型档案字段。
- `csl.c/.h`：dataref 容量 48→64；重排三组连续索引——角度 36–42 / 转速 43–49 / 螺旋桨 50–56，新增 logo 灯 dataref。
- `xconnect.c`：解析 `logo_on`、1–8 发、机型档案字段；parts 日志带出处。
- `players.c`：按 `engine_count` 逐台写角度/转速（`J=1200 / T=2400 / P=3000 / R=1200 RPM`）；起落架兜底改用 AGL + 固定起落架恒放下；补 logo 灯。
- `datarefs.c`：`MAX_ENGINES` 4→8；未知引擎数按实测 on 掩码最高位推断（原固定 2 发）；采集侧原始值日志。

### 3.3 MSFS 插件（MConnect）

- `mconnect.c`：解析与 XConnect 完全相同的 canonical parts（6 灯 / 1–8 发 / gear / flaps / spoilers / 机型档案）。
- `datadefs.c/.h`：新增 `DEF_AI_PARTS`（ID=6，避开 `REQ_SYSSTATE=4`），写 `GEAR HANDLE POSITION`、`TRAILING EDGE FLAPS LEFT/RIGHT PERCENT`、`SPOILERS HANDLE POSITION`、`GENERAL ENG THROTTLE LEVER POSITION:1..4`。
- `players.c`：`LIGHT xxx` SimVar 只读，改按 AI ObjectID 发 `*_LIGHTS_ON/OFF` 事件；两类写入都做能力探测，首次失败即全局禁用并打日志。
- `sc.h`：补 `SC_GROUP_PRIORITY_HIGHEST` / `SC_EVENT_FLAG_GROUPID_IS_PRIORITY`（按 AI ObjectID 发事件必须带后者，否则会作用到用户自己的飞机）。
- `README.md`：更新能力说明，新增 `--parts-probe` 用法。

### 3.4 机型库与打包

- **新增** `xfly_client/aircraft_engine_types.b64`：从 swift `aircrafticao.json` 的 `engine` 字段导出 2585 个 designator 的 J/T/P/R（11 KB）。
- `aircraft_db.lookup()` 返回 `engine_type` / `combined_type`；`AircraftProfile` 优先用官方值，前缀表仅兜底。
- `build_exe.ps1`：补 `aircraft_engine_types.b64` 的 PyInstaller `--add-data`——否则打包版会静默退回旧的类型猜测。

### 3.5 诊断与验证工具

- 三级日志：`raw:`（模拟器原始值）→ `[parts] acc json` / `[parts] roster`（组装后 JSON）→ `anim:`（最终动画值），均按变化/30s 节流。
- **新增** `MConnect.exe --parts-probe`：注入临时 AI 飞机，12 秒后输出 `parts probe: ai_objects=N parts_setdata=OK/FAILED light_events=OK/FAILED`。
- **新增** `tests/test_native_schema.py`：解析 C 源码，校验 dataref 容量/分组连续性、禁止硬编码旧偏移、定义 ID 唯一、两侧 6 灯 key 对齐、探针入口存在、所有 b64 数据库均已打包。

## 5. 兼容性与影响

- **协议**：ACC parts 仍只发服务器认识的 6 个灯键；新增的 `engine_count/engine_type/gear_type/parts_source` 是 roster 附加字段，旧客户端/插件忽略即可。
- **全量/增量**：`is_full_data=true` 时对端先清空旧部件再合并；旧行为（无条件合并）已移除。
- **X-Plane**：最多支持 8 发逐台动画；超过 8 发仍按 8 发处理。
- **MSFS**：灯光/起落架/襟翼/扰流板/油门写入依赖当前 SimConnect 版本对 AI 对象是否开放；能力不足时自动降级，**位置渲染不受影响**。油门只写前 4 台（SimVar `GENERAL ENG THROTTLE LEVER POSITION:1..4` 限制），5–8 发在 MSFS 侧不逐台驱动。
- **构建**：XConnect 与 MConnect 需重新编译并成对使用；客户端打包需包含新增 b64 文件（已由 CI 测试锁住）。
